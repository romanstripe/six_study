# 실전 과제 6 · 고객 불량 회신 보고서 (분석·보고서형, 3시간)

## 상황
고객A(서버 메모리 모듈 회사)에서 품질 문의가 들어왔습니다. 우리 DRAM이 들어간 모듈이 **85°C 고온 시험에서 데이터를 잃는다**는 내용입니다(`data/complaint_고객A.txt`).
DRAM 셀은 작은 축전기라서 전하가 조금씩 새어 나갑니다. 그래서 주기적으로 다시 채우는데(**리프레시**), 고온에서는 더 빨리 새기 때문에 불량이 먼저 드러납니다.
품질보증팀 **오세린 책임**이 팹 데이터를 거꾸로 추적해서 원인과 영향 범위를 찾고, 고객에게 보낼 회신서를 준비해 달라고 합니다.

## 만들 것
1. **분석 스크립트**: 아래 자료를 읽어 결과 파일과 그림을 다시 만들어 내는 코드. 명령 하나로 실행, 실행 방법은 `RUN.md`에
2. **사내 분석 보고서** `REPORT_사내.md`: 맨 앞에 경영진용 요약(5줄 이내), 그다음 근거 데이터·그림·판단 과정
3. **고객 회신서 초안** `REPLY_고객A.md`: 고객A에게 그대로 보낼 수 있는 문서
4. **영향 lot 목록 파일** (형식은 담당자에게 확인)
5. 핵심 계산을 확인하는 **자동 테스트**

언어·도구는 자유입니다.

## 자료 (`data/`)
| 파일 | 내용 |
|---|---|
| `complaint_고객A.txt` | 고객A의 문의 원문 |
| `lot_history.csv` | lot별 공정 이력. step: CLEAN(세정) → DIFF_GOX(게이트 산화막 확산) → METRO_GOX(두께 측정) → EDS(웨이퍼 전기 테스트). eq_id는 설비, track_in_time은 투입 시각 |
| `metrology_gox.csv` | 게이트 산화막 두께 측정값(lot마다 5장). spec_lo~spec_hi가 합격 범위, tool은 측정기 |
| `eds_summary.csv` | lot별 EDS 수율, 고온 리프레시 불량률(%) |
| `shipments.csv` | lot별 출하 고객, 출하일, 모듈 수량 |
| `equipment_log.txt` | 확산·계측 설비 수리·PM 이력 |
| `calibration_log.txt` | 두께 측정기 교정 기록 |
| `fa_note.txt` | 사내 불량 분석(FA) 메모 |

용어
- **게이트 산화막(GOX)**: 트랜지스터의 얇은 절연막. 얇으면 전하가 더 잘 샘
- **확산로(DF)**: 웨이퍼를 고온으로 구워 산화막을 기르는 설비. 온도가 낮으면 막이 얇게 자람
- **측정기(MT)**: 막 두께를 재는 계측 설비
- **EDS**: 웨이퍼 상태에서 칩 하나하나를 전기로 시험하는 공정
- **FA**: 불량품을 잘라 보고 원인을 찾는 분석
- **8D**: 고객 불량 대응에 쓰는 보고 틀(현상·봉쇄·원인·시정·재발 방지 등)
